**Goal:** 移行期間用に残していた旧ディレクトリ（`src/lib`・`src/components`）の除外をアーキテクチャテストから取り除き、`src` 配下のすべての `.ts`/`.tsx` を検査対象にする。あわせて、旧構成を前提にしたコメント・CLAUDE.md・README の記述を新構成に更新する。アプリの挙動は変えない。

**Tech Stack:** TypeScript 5.7, vitest 3（既定 `environment: "node"`）, Node の `fs.readdirSync({ recursive: true })`

**Spec:** `docs/superpowers/specs/2026-09-26-feature-based-clean-architecture-design.md`（本計画は 5 章の移行手順 #7 を実装する。根拠は 2.1・2.2 節の配置と import ルール、6 章のアーキテクチャテスト）。前段の計画 `docs/superpowers/plans/2026-09-26-pr6-scenario-feature.md` の「後続 PR への申し送り」のうち PR 7 分も本計画で扱う。

## 仕様からの補足・判断

1. **`src/lib`・`src/components` の削除は不要**: PR 6 までの移動で両ディレクトリは既に存在しない。本 PR では、再びそこへファイルを置いたり import したりしたらアーキテクチャテストが違反として検出するようにする。
2. **アーキテクチャテスト自身は `tooling` 区分として判定の対象外にする**: `src` 全体を走査すると `src/architecture.test.ts`・`src/architecture/importRules.ts`・`src/architecture/importRules.test.ts` も対象になる。これらは `node:fs`・`node:path` を使い、機能・層のどこにも属さない。`src` の外へ移すと `vitest.config.ts` の `include`（`src/**/*.test.{ts,tsx}`）と仕様 6 章のパスの変更が要るため、置き場所は変えず、分類で除外する。一方、アプリのコードがテスト用の判定関数に依存しないよう、`tooling` を import 先にした場合は違反にする。
   - `tooling` と判定するのは、`src` からのパスの先頭要素が `architecture`（ディレクトリ）または `architecture.test.ts` のときだけ。`architecture.ts` や `architectureHelper.ts` のような似た名前のファイルは `unknown` になり、違反になる。
3. **配置違反はファイル単位でも検出する（`checkPlacement` の新設）**: 現在の `collectViolations` は import 指定子ごとにしか `checkImport` を呼ばないので、import を1つも持たないファイル（定数だけのファイル等）を `src/utils.ts` に置いても検出できない。`src` 全体を対象にする意味を持たせるため、ファイルごとに配置を検査し、配置違反のファイルは import の検査を省いて配置違反だけを報告する（同じ理由が import の数だけ並ぶのを避ける）。
4. **`/game` の First Load JS 増加（PR 6 の申し送り）は本 PR では扱わない**: `sideEffects` 指定や import 経路の変更はビルド成果物を変える最適化で、「旧構成の後片付け」と独立にレビュー・計測したい。別 PR とし、申し送りに残す。
5. **「初期値に戻す」ダイアログの文言の食い違い（PR 6 の申し送り）も本 PR では扱わない**: 挙動の変更を伴うため別 PR。
6. **仕様 2.2 節に配置ルールを1項目追記する**: 「`src/app`・`src/features/<feature>/<layer>`・`src/shared/{domain,lib,ui}` 以外への配置は違反（アーキテクチャテスト自身を除く）」は、これまでテストの実装にはあった（`unknown` の配置）が仕様に書かれていなかった。`src` 全体を対象にするのに合わせて明文化する。

export function checkImport(fromSrcPath: string, specifier: string): string | null {
  const placement = checkPlacement(fromSrcPath);
  if (placement !== null) return placement;
  const from = classify(fromSrcPath);
  if (from.area === "tooling" || from.area === "unknown") return null;
  const isTest = isTestFile(fromSrcPath);
  const target = resolveSpecifier(fromSrcPath, specifier);
  if (target.kind === "package") return checkPackage(from, target.name, isTest);
  if (target.kind === "outside-src") {

  }
  return checkInternal(from, classify(target.srcPath), specifier.startsWith("@/"));

import path from "node:path";
import { fileURLToPath } from "node:url";

import { checkImport, checkPlacement, extractSpecifiers } from "./architecture/importRules";

/**

 * ルールは docs/superpowers/specs/2026-09-26-feature-based-clean-architecture-design.md の 2.2 節。
 */

const SRC_DIR = path.dirname(fileURLToPath(import.meta.url));

/** src 配下の .ts/.tsx を src からの POSIX 相対パスで返す。 */
function listSourceFiles(): string[] {
  return readdirSync(SRC_DIR, { recursive: true, encoding: "utf8" })
    .filter((file) => /\.tsx?$/.test(file) && !file.endsWith(".d.ts"))
    .map((file) => file.split(path.sep).join("/"));
}

/** 配置違反のファイルは import を検査せず、配置違反だけを報告する。 */
function collectViolations(): string[] {
  return listSourceFiles().flatMap((file) => {
    const placement = checkPlacement(file);
    if (placement !== null) return [`${file}: ${placement}`];
    return extractSpecifiers(readFileSync(path.join(SRC_DIR, file), "utf8")).flatMap((specifier) => {
      const reason = checkImport(file, specifier);
      return reason === null ? [] : [`${file} → ${specifier}: ${reason}`];
    });
  });
}
