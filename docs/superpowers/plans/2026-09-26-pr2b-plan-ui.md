# PR 2b: plan のストアとフォームの plan/ui への移動 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** plan のストア（`src/lib/store/usePlanStore.ts`）と入力フォーム（`src/components/forms/*`。`usePlanErrors.ts` を含む）を `src/features/plan/ui` へ移し、外部からは `@/features/plan/ui` の index 経由で使うようにする。ストアの形（state・アクション・persist 設定）は一切変えない。挙動・見た目も変えない。

**Architecture:** `src/features/plan/ui/index.ts` を plan/ui の公開 API とする。plan/ui 内のファイル同士は相対パス（`./usePlanStore`）で個別ファイルを import し、自層の index は import しない（index → フォーム → index の循環を作らないため）。同一機能の他の層は PR 2a と同じく `@/features/plan/<layer>` の index で import する。スナップショット関連（`snapshots`・`saveSnapshot` 等と `Snapshot` 型）は PR 6 までストアに残す。

**Tech Stack:** TypeScript 5.7, Next.js 15（App Router、`"use client"`）, React 19, Zustand（persist）, vitest 3（既定 `environment: "node"`、コンポーネントテストは `// @vitest-environment jsdom`）

**Spec:** `docs/superpowers/specs/2026-09-26-feature-based-clean-architecture-design.md`（本計画は 5 章の移行手順 #2b を実装する。2.1・2.2 節の層と import ルール、4 章の plan のファイル対応表の `usePlanStore.ts` と `components/forms/*` の行が根拠）。前段の計画 `docs/superpowers/plans/2026-09-26-pr2a-plan-domain.md` の「後続 PR への申し送り」のうち PR 2b 分も本計画で扱う。

## 仕様からの補足・判断

1. **`mergePersistedPlanState` はストアに残す**: 仕様 3.1 節では `plan/infrastructure` へ移すとしているが、ストアの分解は PR 3 の範囲。本 PR ではストアのファイルを丸ごと移すだけにする。テスト（`usePlanStore.test.ts`）は同一層なので `./usePlanStore` から直接 import し続け、index には出さない。
2. **plan/ui の index が公開するもの**: 層外から実際に使われているものだけにする。`usePlanStore`・`Snapshot` 型（`ComparisonChart.tsx` が使用）・8 つのフォームコンポーネント。`usePlanErrors`・`mergePersistedPlanState`・`SnapshotOrigin` は層内でしか使われていないので出さない。
3. **`number-input.integration.test.ts` は `src/components/forms/` に残す**: PR 2a の判断どおり（`runSimulation` に依存するため、PR 4 で `simulation/ui` へ移す）。本 PR 後、`src/components/forms/` にはこの 1 ファイルだけが残る。
4. **`planFile.test.ts` の「読み込み失敗時に現在のプランが不変」**: PR 2a の申し送りどおり、この describe を `plan/ui/usePlanStore.test.ts` の末尾へ移す（infrastructure → ui の違反を避けるため）。テスト本体は変えず、使っている補助関数 `rich`・`serializeRaw` は移動先にも同じ内容で置く（`planFile.test.ts` の他のテストも使うので元からは消さない）。
5. **旧ディレクトリへの依存を持つテスト**: `plan/ui/usePlanStore.test.ts` は `@/lib/simulation/engine`・`@/lib/simulation/types` を import している。旧ディレクトリへの import はアーキテクチャテストの判定対象外なので本 PR では変えない。PR 4 で simulation が `features` に移ると「下流機能の import」違反になるため、下の申し送りに追加する。
6. **README の「構成」節**（`src/lib/store/` の記述）: PR 1・2a でも更新しておらず、旧構成の記述全体がずれている。PR 7（cleanup）で CLAUDE.md と一緒に書き直すものとし、本 PR では触らない。

## Review Focus

1. **既存ユーザーの保存データ**: localStorage の `life-plan/v1` に保存済みの入力が、移動後もそのまま復元されること。ストアのファイルを変更しないので persist キー・`version`・`merge` は同一のはずだが、Task 3 の画面確認で必ず見る（自動テストの `usePlanStore — 永続化復元時の期間自動補正` は merge 関数単体しか見ていない）。
2. **自層 index の循環 import**: plan/ui 内のファイルが `@/features/plan/ui` を import すると、index → フォーム → index の循環になり、テストやビルドで `undefined` のコンポーネント／ストアを参照して壊れる。アーキテクチャテストはこれを違反としないので、Task 2 で grep による確認を行う。
3. **Next.js のクライアント境界**: index.ts には `"use client"` を付けない。フォームの各ファイルが持つ `"use client"` はそのまま残し、`src/app/page.tsx`（クライアントコンポーネント）から index 経由で import してビルドが通ることを `npm run build` で確認する。
4. **`/game` のバンドル**: `src/app/game/page.tsx` も index 経由でストアを import するため、使わないフォームがバンドルに入る可能性がある。Task 0 と Task 3 で `npm run build` のルート別サイズ（`/game` の First Load JS）を比べ、増えていれば PR の本文に数値を書く（仕様上 index 経由は必須なので、増加は許容して記録に留める）。
5. **テスト件数の維持**: describe の移動でテストが消えたり二重になったりしないこと。各 Task 後に Task 0 のテストファイル数・テスト数と一致することを確認する。
